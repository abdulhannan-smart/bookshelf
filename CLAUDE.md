# BookShelf — AI Context File

BookShelf is a book catalogue REST API + React frontend, npm-workspaces monorepo. Think simplified Goodreads.

---

## Tech Stack

JSON files in `/data` are the data store — no database, intentional. Everything else is in `package.json`.

---

## Folder Structure

What's not obvious from `ls`:

- `apps/api/src/data/` — the ONLY place that reads or writes `data/*.json`.
- `apps/api/src/routes/` — parse request, call service, send response. No validation here.
- `apps/api/src/services/` — business logic AND input validation.
- `packages/shared/src/index.ts` — types shared by `apps/api` and `apps/web`. Changes must compile both.
- `data/books.json` — 30 seeded books, do not delete.
- `data/reviews.json` — starts as `[]`, populated via the reviews endpoints.
- `apps/api/mcp-server.ts` — standalone MCP dev tool. Reads `data/*.json` directly via `fs`; it is NOT a route/service and is the one allowed exception to the data-layer rule.

---

## API Response Shape

Every endpoint returns this shape, no exceptions:

```json
// Success
{ "success": true, "data": <payload>, "count": <number> }

// Error
{ "success": false, "error": "<message>", "statusCode": <number> }
```

`count` only appears on list/search endpoints. `statusCode` mirrors the HTTP status (e.g. 400, 404, 500).

---

## ID Format

- Books:   `book_`   + 8 hex chars — e.g. `book_a1b2c3d4`
- Shelves: `shelf_`  + 8 hex chars
- Reviews: `review_` + 8 hex chars

Generated by `uuid v4`, sliced to the first 8 chars, then prefixed.

---

## Data Layer Rules

- `jsonStore.ts` is the only file in `apps/api/src/` that calls `fs.readFile` / `fs.writeFile`.
- Each resource has its own repository (`booksRepository.ts`, `reviewsRepository.ts`) wrapping all CRUD for one JSON file. Routes/services call the repository, never `fs` directly.
- Write pattern: read full array → mutate in memory → write full array back. No partial writes, no streaming.
- No concurrency handling — intentional, do not add.

---

## Validation Rules (enforced in services, not routes)

`POST /api/books` requires:

- `title`  — string, max 200 chars
- `author` — string
- `genre`  — string, exact case, one of: `Technology` | `Fiction` | `Science` | `History` | `Self-Help`
- `year`   — number, between 1000 and the current year inclusive
- `isbn`   — string

`POST /api/books/:id/reviews` requires:

- The book id in the URL must exist — otherwise 404 before any body validation runs.
- `reviewer` — string, required
- `rating`   — number, between 1 and 5 inclusive
- `body`     — string, required

Validation lives in `services/booksService.ts` and `services/reviewsService.ts`. Routes call the service and let errors bubble to `errorHandler`.

## Current Endpoints

```
GET    /api/health
GET    /api/books
GET    /api/books/search?q=
GET    /api/books/:id
POST   /api/books
DELETE /api/books/:id
GET    /api/books/:id/reviews
POST   /api/books/:id/reviews
```

GOTCHA: `/search` MUST be declared before `/:id` in the router. Otherwise Express matches `"search"` as a book id and returns 404.

The reviews routes live in their own router (`routes/reviews.ts`) mounted at `/api/books`, alongside `booksRouter`. The two routers do not conflict because review paths are `/:id/reviews` (two segments) and book routes are `/:id` (one segment).

## Testing Conventions

- Jest + Supertest, AAA pattern (Arrange, Act, Assert).
- Integration tests import `app` from `src/app.ts`; Supertest fires requests without booting a live server.
- `books.json` is snapshotted in `beforeAll` and restored in `afterAll` — tests must never leave seed data mutated.
- Run from repo root: `npm run test`. Coverage: `npm run test:coverage --workspace=apps/api`.

---

## Frontend Conventions

- API calls go through `src/lib/api.ts` — never `fetch` directly from a component.
- Use `import type` for interfaces from `api.ts` (Vite + `verbatimModuleSyntax` requires it) — e.g. `import type { Book } from "../lib/api"`.
- Colour palette: cream background, brown text, forest green for focus/accent.
- Responsive grid: 1 col mobile → 2 col tablet → 3 col desktop.
- Routing is hash-based, hand-rolled in `App.tsx` (`#/` → catalogue, `#/books/:id` → detail). Do NOT add `react-router-dom` — two pages do not justify the dependency.

---

## What NOT To Do

- Do NOT add a real database — JSON files are intentional.
- Do NOT read/write JSON files from routes or services — go through `apps/api/src/data/`.
- Do NOT use `any` — use `unknown` and narrow.
- Do NOT leave `console.log` in committed code.
- Do NOT add npm dependencies without a clear reason.
- Do NOT modify `packages/shared` types without recompiling both `apps/api` and `apps/web`.
- Do NOT add concurrency handling to the JSON store — out of scope.
- Do NOT put validation in route handlers — it belongs in services.
- Do NOT declare `/:id` before `/search` in the router — search will break.

---

## Known Limitations

- No authentication — all endpoints public.
- No pagination — `GET /api/books` returns all books every time.
- Concurrent writes can lose data — last write wins.
- `coverUrl` is always `null` — no image upload support.
- Port `3001` is hardcoded in `apps/api/src/index.ts` — no env config yet.
